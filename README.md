# Brain Age Prediction VBM

Brain age prediction using decentralized SVR with VBM (voxel-based morphometry) grey-matter density maps as features. Adapted from [NeuroFlame/nfc-brainage-prediction-fnc-gica](https://github.com/NeuroFlame/nfc-brainage-prediction-fnc-gica) (which used FNC/GICA connectivity matrices instead of VBM images), itself ported from [trendscenter/coinstac-brainage-fnc](https://github.com/trendscenter/coinstac-brainage-fnc) to the NeuroFLAME / NVFlare federated learning framework. The federated SVR algorithm is unchanged — only the input data format and feature extraction differ. `input_source` still supports `"GICA"` and `"UKBioBank_Comp2019"` for backward compatibility.

---

## Algorithm

A two-round federated computation:

**Round 0** — Non-owner sites each train a local `LinearSVR` on their full dataset and send back the learned weight vector. The owner site caches its train/test split for round 1.

**Round 1 (server)** — The server stacks all local weight vectors into a matrix `w_locals` (shape: `n_features × n_sites`) and broadcasts it to all sites.

**Round 1 (owner site)** — The owner projects its cached data through the averaged local weights (`U = X @ mean(w_locals)`), then trains a second `LinearSVR` on the projected features. Final metrics are written to disk.

## Input Data

Each site directory under `test_data/` must contain:

- `covariates.csv` — CSV with at minimum `niftifilename` and `age` columns. Any other columns (e.g. `site`, `sex`, `isControl`) are ignored by the computation.
- One `.nii`/`.nii.gz` file per subject, named exactly as listed in the `niftifilename` column of `covariates.csv`, all sharing the same voxel grid (dimensions and orientation) — e.g. SPM `swc1*` smoothed/warped/modulated grey-matter density maps in MNI space.

Rows in `covariates.csv` with a missing filename or age are dropped automatically.

## Computation Parameters

Edit `test_data/server/parameters.json` to configure the run:

| Parameter | Description | Default |
|-----------|-------------|---------|
| `owner_site` | Site name (or ID) of the holdout/owner site. No site acts as owner if omitted. | `""` |
| `data_file` | FNC `.mat` filename. Unused when `input_source` is `"VBM"` (each subject has its own NIfTI file). | `null` |
| `label_file` | Covariates CSV filename | `"covariates.csv"` |
| `input_source` | `"VBM"`, `"GICA"`, or `"UKBioBank_Comp2019"` | none — required |
| `vbm_downsample_factor` | VBM only — stride applied to each spatial axis of the NIfTI volumes to shrink the voxel count (e.g. `2` keeps every other voxel per axis, an 8x reduction). Must be identical across all sites so feature vectors line up. | `1` |
| `split_type` | `"random"` or `"age_range_stratified"` | none — required |
| `test_size` | Fraction of subjects for test set | none — required |
| `shuffle` | Shuffle before splitting | none — required |
| `svr_params_local` | `LinearSVR` kwargs for non-owner sites | none — required |
| `svr_params_owner` | `LinearSVR` kwargs for owner site (round 1) | none — required |
| `site_id_name_map` | Optional map of NVFlare site IDs to human-readable names | `{}` |

`input_source`, `split_type`, `test_size`, `shuffle`, `svr_params_local`, and `svr_params_owner` have no code-level fallback — omitting any of them raises a `KeyError` at runtime, so treat "Default" above as "value used in the shipped example," not an implicit fallback. The bundled `test_data/server/parameters.json` sets `vbm_downsample_factor` to `2` (rather than the code's default of `1`) to keep the sample run fast.

## Running Locally (Simulation)

The `app/code` modules (`executor`, `aggregator`, `controller`, `_utils`) are imported by class path (see `app/config/*.json`), so `app/code` must be on `PYTHONPATH`. Inside `Dockerfile-dev` this is already set; running natively, export it yourself first:

```bash
export PYTHONPATH="$(pwd)/app/code"
```

**Step 1:** Generate the job folder for your sites:

```bash
python makeJob.py site1,site2
```

**Step 2:** Run the NVFlare simulator:

```bash
python debug.py job -w simulator_workspace -c site1,site2 -n 2 -t 2
```

Results are written to `test_output/<job_id>/<site_name>/`. The bundled `test_data/` ships `site1` (owner) and `site2` (member); add more `siteN` directories under `test_data/` (each with its own `covariates.csv` and NIfTI files) and extend both commands' site lists to run with more sites.

## Notes on COINSTAC → NeuroFLAME Translation

| COINSTAC | NeuroFLAME / NVFlare |
|----------|----------------------|
| `local.py local_0()` | `executor.py` → `TASK_NAME_GET_LOCAL_SVR_WEIGHTS` |
| `local.py local_1()` | `executor.py` → `TASK_NAME_ACCEPT_AGGREGATED_WEIGHTS` |
| `remote.py remote_0()` | `aggregator.py` round-0 `accept()` + `aggregate()` |
| `remote.py remote_1()` | `aggregator.py` round-1 `accept()` |
| `state['owner']` / `clientId` check | `computation_parameters["owner_site"]` vs `fl_ctx.get_identity_name()` |
| `args['cache']` (disk) | `fl_ctx.set_prop("cached_splits", ...)` (in-memory, sticky) |
| stdin/stdout JSON protocol | `Shareable` dict |
| `compspec.json` inputs | `test_data/server/parameters.json` |
